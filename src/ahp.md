# Agent Host Protocol 0.9.0 — adapter reference

What milestones 2–4 need, verified against `node_modules/@microsoft/agent-host-protocol/` 0.9.0 and the published spec. Where the two
disagree the types win (§11).

The AHP integration remains on the colocated `DurableChannelHub` and its global `serverSeq`/scalar reconnect contract. The separate
`DurableChannelRouter`/`DurableChannelGateway` implementation speaks `durable-channel/distributed-1`, uses per-channel generations and
cursor maps, and is not AHP-compatible. The existing seven-method `createRpc` surface is also not itself the AHP adapter: the translation
and official-client integration remain in `src/ahp.test.ts`. No distributed AHP sequencer or translation log is provided.

## 1. Purpose and scope

| Concept           | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framing           | JSON-RPC 2.0 over any reliable, ordered, bidirectional, message-integral transport. No transport is mandated; WebSocket is the default.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Channel           | A URI-identified subscribable resource. Every command's and notification's `params` carries a top-level `channel: URI`, so a peer routes on `(method, params.channel)` alone.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| State channel     | State mutated only by actions run through a pure reducer; replaying actions in `serverSeq` order on any prior snapshot yields identical state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Write-ahead       | The client applies its own action optimistically, sends `dispatchAction`, and the server echoes the action as an `ActionEnvelope` to every subscriber.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Stateless channel | Returns `{}` from `subscribe` and uses channel-specific methods instead of `action` envelopes. This project has none.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| In scope          | `ahp-root://`, `ahp-session:/<uuid>`, `ahp-chat:/<cid>` and the sixteen methods and notifications of §5.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Out of scope      | terminals (`ahp-terminal:/<id>`, `createTerminal`, `disposeTerminal`), changesets (`ahp-changeset:/<id>`, `invokeChangesetOperation`), annotations, automations (`ahp-automations://`, `ahp-automation-run:/<id>`, `runAutomation`, `fetchAutomationRuns`, `listAutomationTriggerDefinitions`), OTLP (`ahp-otlp:`, `otlp/export*`), resource watch (`ahp-resource-watch:/<id>`, `createResourceWatch`), the bidirectional `resource*` filesystem family, authentication (`authenticate`, `auth/required`), MCP and customizations, progress (`root/progress`), `completions`, `resolveSessionConfig`, `sessionConfigCompletions`. |

## 2. Transport and framing

| Rule                | Detail                                                                                                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Socket              | WebSocket; the server is the WebSocket server and messages are text frames.                                                                                                                                                           |
| Frame               | "Each text frame contains exactly one complete JSON-RPC message." The client also decodes binary frames as UTF-8.                                                                                                                     |
| Request             | `{ jsonrpc: "2.0", id: number, method, params }` — `id` is a number, never a string; exactly one response carries the same `id`.                                                                                                      |
| Notification        | `{ jsonrpc: "2.0", method, params }` — no `id`, never answered.                                                                                                                                                                       |
| Batching            | Not supported: `ProtocolMessage` has no array form and the client's inbound dispatcher handles single objects only.                                                                                                                   |
| `channel` on params | Mandatory on every command and notification in both directions.                                                                                                                                                                       |
| Connection-level    | `initialize`, `ping`, `reconnect`, `listSessions`, `authenticate`, `resolveSessionConfig`, `sessionConfigCompletions` and `resource*` narrow `channel` to the literal `"ahp-root://"`. Everything else uses the owning channel's URI. |
| `ping`              | "The server MUST respond regardless of whether the client has completed `initialize` or holds any subscriptions."                                                                                                                     |
| Server → client     | Only the `resource*` family may be server-initiated; any other inbound request is answered `-32601` by the official client.                                                                                                           |
| Endpoint auth       | A transport concern outside AHP (query string, HTTP headers), settled before `initialize`.                                                                                                                                            |

## 3. Lifecycle

| Step                   | Shape                                                                                                                                                                                                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `initialize` params    | `{ channel: "ahp-root://", protocolVersions: string[], clientId, clientInfo?, initialSubscriptions?: URI[], locale?, capabilities? }`. `protocolVersions` is most-preferred first, each `MAJOR.MINOR.PATCH`. `clientInfo` is informational only. `capabilities.mcpApps` is the only flag defined. |
| `initialize` result    | `{ protocolVersion, serverSeq, snapshots: Snapshot[], serverInfo?, _meta?, defaultDirectory?, completionTriggerCharacters?, terminalCommandPrefix?, telemetry?, automations? }`. First three required; `snapshots` may be empty. This project populates only the required three.                  |
| Version negotiation    | The server picks one offered entry and returns it; "Both peers MUST use the selected version for the rest of the connection."                                                                                                                                                                     |
| Negotiation failure    | "If the server cannot speak any of the offered versions, it MUST respond with `UnsupportedProtocolVersion` (`-32005`) and required `data.supportedVersions` instead of a result, and close the connection."                                                                                       |
| Versions               | `PROTOCOL_VERSION = "0.9.0"`; `SUPPORTED_PROTOCOL_VERSIONS = ["0.9.0","0.8.0","0.7.0","0.6.0","0.5.2","0.5.1"]`.                                                                                                                                                                                  |
| `initialSubscriptions` | Subscribed inside the same request; the result carries one `Snapshot` per state-bearing URI.                                                                                                                                                                                                      |
| `reconnect` params     | `{ channel: "ahp-root://", clientId, lastSeenServerSeq, subscriptions: URI[] }`.                                                                                                                                                                                                                  |
| `reconnect` → replay   | `{ type: "replay", actions: ActionEnvelope[], missing: URI[] }`. "The server MUST include all replayed data in the response."                                                                                                                                                                     |
| `reconnect` → snapshot | `{ type: "snapshot", snapshots: Snapshot[] }` when the gap exceeds the replay buffer.                                                                                                                                                                                                             |
| `missing`              | Requested URIs the server cannot resume — disposed resources, or ones the client may no longer observe. Clients SHOULD drop them.                                                                                                                                                                 |
| Not replayed           | Protocol notifications (`root/session*`, `root/progress`, `auth/required`) and stateless-channel traffic. The client SHOULD re-fetch `listSessions` after every reconnect.                                                                                                                        |
| `subscribe`            | Params `{ channel, delivery?: { maxLatencyMs }, view?: { turns } }` → `{ snapshot?: Snapshot }` (omitted for stateless channels). Both options are advisory: "the server MAY return more or fewer turns than requested" and "Clients MUST tolerate receiving more state than requested."          |
| `unsubscribe`          | Fire-and-forget notification carrying only `{ channel }`.                                                                                                                                                                                                                                         |

## 4. Sequencing and envelopes

| Element            | Rule                                                                                                                                                                                                                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `serverSeq`        | One global counter per server, not per channel; incremented by every committed envelope, rejected ones included.                                                                                                                                                                                                                                                |
| `fromSeq`          | On a `Snapshot`: the `serverSeq` it was taken at. "Subsequent actions will have `serverSeq > fromSeq`."                                                                                                                                                                                                                                                         |
| `clientSeq`        | Per-connection counter owned by the client. Starts at 1 on every new `AhpClient` and increments per `dispatch`.                                                                                                                                                                                                                                                 |
| `ActionEnvelope`   | `{ channel, action, serverSeq, origin: { clientId, clientSeq } \| undefined, rejectionReason? }`.                                                                                                                                                                                                                                                               |
| `action` payload   | Intrinsic fields only — `{ type, ...fields }`. The channel comes from the envelope, never from the action.                                                                                                                                                                                                                                                      |
| `origin`           | Present when a client dispatched the action; absent for server-origin actions.                                                                                                                                                                                                                                                                                  |
| `rejectionReason`  | The server refused the action: state untouched, but a `serverSeq` was consumed and every subscriber still receives the envelope.                                                                                                                                                                                                                                |
| Echo               | Every envelope, accepted or rejected, goes to all subscribers of the channel — the originating connection included.                                                                                                                                                                                                                                             |
| Ordering           | Envelopes arrive in ascending `serverSeq` on an ordered transport; the reducer contract depends on it.                                                                                                                                                                                                                                                          |
| Replay vs snapshot | Replay while the ring still covers everything `> lastSeenServerSeq`; otherwise fresh snapshots. After a restart the ring is empty, so only a fully caught-up client gets a replay.                                                                                                                                                                              |
| Client reconcile   | The client keeps `confirmedState`, `pendingActions[]` and a derived `optimisticState`. Its own confirmed echo pops the head of `pendingActions`; an external envelope is applied and the pending list rebased; a `rejectionReason` envelope pops the entry and discards its optimistic effect. `reconnect` resets `confirmedState` and clears `pendingActions`. |

## 7. Channel reference

### 7.1 `ahp-root://` — two slashes, exactly one per server

| `RootState`       | Notes                                                                                                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `agents`          | Required `AgentInfo[]`, each `{ provider, displayName, description, models, protectedResources?, customizations?, capabilities? }`. Populated.                         |
| `activeSessions?` | Count of non-disposed sessions. Populated.                                                                                                                             |
| Left absent       | `terminals?: TerminalInfo[]`, `config?: RootConfigState` (schema + values), `_meta?` opaque host metadata.                                                             |
| Session catalogue | Deliberately **not** in root state — it can be arbitrarily large. Clients fetch it with `listSessions` and keep the cache live with the `root/session*` notifications. |

| Root action                  | Fields               | Origin | Reducer                                                                                                |
| ---------------------------- | -------------------- | ------ | ------------------------------------------------------------------------------------------------------ |
| `root/agentsChanged`         | `agents`             | server | Replaces `agents`.                                                                                     |
| `root/activeSessionsChanged` | `activeSessions`     | server | Replaces `activeSessions`.                                                                             |
| `root/terminalsChanged`      | `terminals`          | server | Full replacement of `terminals`.                                                                       |
| `root/configChanged`         | `config`, `replace?` | client | Merges into `config.values`, or replaces them when `replace`. **No-op when `state.config` is absent.** |

| Root notification            | Params               | Semantics                                                                                                                                                         |
| ---------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `root/sessionAdded`          | `summary`            | A session was created.                                                                                                                                            |
| `root/sessionRemoved`        | `session`            | A session was disposed.                                                                                                                                           |
| `root/sessionSummaryChanged` | `session`, `changes` | Only changed mutable fields. Identity fields (`resource`, `provider`, `createdAt`) never change and MUST be omitted. A client with no cached entry MAY ignore it. |

All three are ephemeral and are **not** replayed on reconnect.

### 7.2 `ahp-session:/<uuid>` — one slash, client-chosen UUID

| `SessionState`     | Fields                                                                                                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inlined metadata   | `provider`, `title`, `status` (required) and `activity?`, `origin?`, `project?`, `workingDirectories?`, `annotations?`.                                                                   |
| Session-only       | `lifecycle`, `activeClients`, `chats` (all required) and `creationError?`, `serverTools?`, `defaultChat?`, `config?`, `customizations?`, `changesets?`, `inputNeeded?`, `_meta?`.         |

| `SessionSummary`   | The inlined metadata plus `resource`, `createdAt`, `modifiedAt` (ISO 8601), `changes?`, `_meta?`.                                                                                         |
| `SessionLifecycle` | `"creating"` → `"ready"` \| `"failed"`.                                                                                                                                                   |

| `SessionStatus` — bitset, reused verbatim by `ChatState.status` and `ChatSummary.status`                                                                                  | Value |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `Idle` — no turn is active                                                                                                                                                | `1`   |
| `Error` — ended with an error                                                                                                                                             | `2`   |
| `InProgress` — a turn is actively streaming                                                                                                                               | `8`   |
| `InputNeeded` — in progress but blocked on the user; implies `InProgress`                                                                                                 | `24`  |
| `IsRead` — viewed since its last modification                                                                                                                             | `32`  |
| `IsArchived`                                                                                                                                                              | `64`  |

| `session/chatRemoved`                                   | `chat`                      | server | Removes the entry and clears `defaultChat` if it named that chat.                                |
| `session/chatUpdated`                                   | `chat`, `changes`           | server | Merges `changes` (ignoring `resource`) onto the entry; no-op if unknown.                         |
| `session/defaultChatChanged`                            | `defaultChat?`              | server | Sets `defaultChat`.                                                                              |
| `session/titleChanged`                                  | `title`                     | client | Sets `title`.                                                                                    |
| `session/isReadChanged`, `session/isArchivedChanged`    | `isRead` / `isArchived`     | client | Sets or clears the `IsRead` / `IsArchived` bit.                                                  |
| `session/activityChanged`                               | `activity`                  | server | Sets `activity`, which may be `undefined`.                                                       |
| `session/serverToolsChanged`                            | `tools`                     | server | Replaces `serverTools`.                                                                          |
| `session/activeClientSet`, `…Removed`                   | `activeClient` / `clientId` | client | Upserts or removes an entry of `activeClients` keyed by `clientId`.                              |

| `session/inputNeededSet`, `…Removed`                    | `request` / `id`            | server | Upserts or removes by `id`, then recomputes the activity bits; an empty list is deleted.         |
| `session/changesetsChanged`                             | `changesets`                | server | Replaces or deletes `changesets`.                                                                |
| `session/configChanged`                                 | `config`, `replace?`        | client | Merges into `config.values`. No-op when `state.config` is absent.                                |
| `session/metaChanged`                                   | `_meta`                     | server | Replaces `_meta`.                                                                                |
| `session/customizations*` (4), `session/mcpServer*` (3) | see source                  | mixed  | Customization and MCP tree edits — out of scope, never emitted.                                  |

| Normative invariant | Statement                                                                                                                                                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Chat catalogue      | Lives in `SessionState.chats` as `ChatSummary`. `ChatState` denormalizes the same fields and producers MUST keep them consistent, announcing every change on the parent session with `session/chatUpdated`.                                                                                            |
| Summary aggregation | `status` comes from `defaultChat` (or the most-recently-modified chat), promoting `InputNeeded` or `Error` if any chat has them; `activity` mirrors that chat; `modifiedAt` is the maximum over chats; `workingDirectories` is session-level and not aggregated upward.                                |
| `inputNeeded`       | Any entry other than `toolClientExecution` implies `SessionStatus.InputNeeded` on the summary; client-execution entries leave activity unchanged. Response paths: `chatInput` → `chat/inputCompleted`, `toolConfirmation` → `chat/toolCallConfirmed`, `toolClientExecution` → `chat/toolCallComplete`. |
| Validation          | The server MUST reject actions referencing a non-existent chat (and `session/defaultChatChanged` whose URI is not in the catalogue), echoing them with `rejectionReason`.                                                                                                                              |

### 7.3 `ahp-chat:/<cid>` — one slash

| Type                        | Shape                                                                                                                                                                                                                                                                      |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Turn` / `ActiveTurn`       | `{ id, startedAt?, duration?, message, responseParts, usage: UsageInfo \| undefined, state: TurnState }` / same without `duration`/`state` and with `startedAt` required.                                                                                                  |
| `TurnState`                 | `"complete"` \| `"cancelled"` \| `"error"`.                                                                                                                                                                                                                                |
| `Message` / `MessageOrigin` | `{ text, origin, attachments?, model?, agent?, _meta? }` / `{ kind: MessageKind }`.                                                                                                                                                                                        |
| `MessageKind`               | `"user"` \| `"agent"` \| `"tool"` \| `"automation"` \| `"systemNotification"`. A real `enum`, so usable as a value.                                                                                                                                                        |
| `ResponsePartKind`          | `"markdown"` \| `"contentRef"` \| `"toolCall"` \| `"reasoning"` \| `"systemNotification"` \| `"inputRequest"` \| `"error"`.                                                                                                                                                |
| `MarkdownResponsePart`      | `{ kind: "markdown", id, content }` — `id` is the `chat/delta` target. `ReasoningResponsePart` is the same shape with `kind: "reasoning"`.                                                                                                                                 |
| `ErrorResponsePart`         | `{ kind: "error", error: ErrorInfo, resumable? }` — only `resumable: true` enables `chat/turnResume`.                                                                                                                                                                      |
| `PendingMessage`            | `{ id, message }`; `PendingMessageKind` is `"steering"` \| `"queued"`.                                                                                                                                                                                                     |
| `UsageInfo`                 | `{ inputTokens?, outputTokens?, model?, cacheReadTokens?, _meta? }`.                                                                                                                                                                                                       |
| `turnsNextCursor`           | Presence means `turns` is a tail window and older turns exist; pass it to `fetchTurns`.                                                                                                                                                                                    |
| `ChatState`                 | Denormalizes `ChatSummary` (`resource`, `title`, `status`, `modifiedAt` required; `activity?`, `origin?`, `interactivity?`, `workingDirectories?`) and adds `turns: Turn[]`, `turnsNextCursor?`, `activeTurn?`, `steeringMessage?`, `queuedMessages?`, `draft?`, `_meta?`. |

| Chat action                                                    | Fields                                                                                                                                         | Origin | Reducer                                                                                                                                                                                                                  |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `chat/turnStarted`                                             | `turnId`, `startedAt`, `message`, `queuedMessageId?`                                                                                           | client | Opens `activeTurn` with empty `responseParts`, sets `modifiedAt = startedAt`, clears `IsRead`, drops the named pending message.                                                                                          |
| `chat/delta`, `chat/reasoning`                                 | `turnId`, `partId`, `content`                                                                                                                  | server | Appends to that markdown / reasoning part's `content`.                                                                                                                                                                   |
| `chat/responsePart`                                            | `turnId`, `part`                                                                                                                               | server | Appends the part. **Error parts are ignored** — use `chat/error`.                                                                                                                                                        |
| `chat/usage`                                                   | `turnId`, `usage`                                                                                                                              | server | Sets `activeTurn.usage`.                                                                                                                                                                                                 |
| `chat/turnComplete`                                            | `turnId`, `duration`                                                                                                                           | server | Finalizes `activeTurn` into `turns` with state `complete`, clamps `duration >= 0`, sets `modifiedAt = startedAt + duration`, forces non-terminal tool calls to `cancelled`/`skipped`.                                    |
| `chat/turnCancelled`                                           | `turnId`, `duration`                                                                                                                           | client | Same, state `cancelled`.                                                                                                                                                                                                 |
| `chat/error`                                                   | `turnId`, `duration`, `part`                                                                                                                   | server | Same, state `error`, appends the error part, sets the `Error` bit.                                                                                                                                                       |
| `chat/turnResume`                                              | `turnId`                                                                                                                                       | client | Only with no `activeTurn` and a last turn in state `error` carrying a resumable error: pops it back to `activeTurn`.                                                                                                     |
| `chat/activityChanged`                                         | `activity?`                                                                                                                                    | server | Sets `activity`.                                                                                                                                                                                                         |
| `chat/workingDirectorySet`, `…Removed`                         | `directory`                                                                                                                                    | client | Appends / removes. ## 8. Official TypeScript client behaviour we must satisfy

| Client behaviour                                                                                                                                                                                                                                   | Server obligation                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dispatch(channel, action, clientSeq?)` sends the **notification** `dispatchAction` and returns only `{ clientSeq }`; it never awaits an echo and a response frame to a notification is dropped.                                                   | Never answer `dispatchAction`; report the outcome only through the `action` echo.                                                                                                                                                                                                                                                                                                                        |
| `clientSeq` starts at 1 on every new `AhpClient`; a supplied value bumps the counter to `max(current, clientSeq + 1)`.                                                                                                                             | Dedupe `clientSeq` **per link**, never per `clientId`. Never persist the watermark; reset it on `connect`.                                                                                                                                                                                                                                                                                               |
| `MultiHostClient` builds a fresh `AhpClient` on every (re)connect with the same `clientId`, resolved once through a `ClientIdStore`.                                                                                                               | A `connect` for an already-connected `clientId` replaces the previous connection: clear its subscriptions and never call its `send` again.                                                                                                                                                                                                                                                               |
| Reconnect flow: with `serverSeq > 0` **and** a non-empty subscription set it calls `reconnect`, falling back to `initialize` with `initialSubscriptions` on any `RpcError` (transport errors propagate); otherwise it calls `initialize` directly. | Both entry points must accept the same subscription set and produce equivalent state; a refusal must be an `RpcError`, not a socket close.                                                                                                                                                                                                                                                               |
| It then always calls `listSessions` with `{ channel: "ahp-root://" }` and no paging; errors are tolerated.                                                                                                                                         | `listSessions` must work immediately after either handshake.                                                                                                                                                                                                                                                                                                                                             |
| It never sends `subscribe` after a `reconnect`.                                                                                                                                                                                                    | `reconnect` must itself restore every resumable subscription.                                                                                                                                                                                                                                                                                                                                            |
| Replay envelopes are applied and fanned out **before** the host is reported `connected`.                                                                                                                                                           | Return every missed envelope inside the `reconnect` response; never push them separately.                                                                                                                                                                                                                                                                                                                |
| `missing` URIs, and prior URIs absent from a `snapshot` result, are dropped from the local subscription set.                                                                                                                                       | Report unresumable URIs precisely; the snapshot variant must carry one snapshot per surviving URI.                                                                                                                                                                                                                                                                                                       |
| `HostRuntime` offers only `[PROTOCOL_VERSION]` and sends no `clientInfo`/`capabilities`; a bare `AhpClient` offers whatever the caller passes.                                                                                                     | Accept a single-entry offer; treat `clientInfo` and `capabilities` as optional. Version-negotiation tests need a bare client.                                                                                                                                                                                                                                                                            |
| Inbound notifications understood: `action`, `root/sessionAdded`, `root/sessionRemoved`, `root/sessionSummaryChanged`, `auth/required`. All others are dropped silently.                                                                            | Do not rely on any other notification reaching the client.                                                                                                                                                                                                                                                                                                                                               |
| Request ids are numbers starting at 1, matched by id; a JSON-RPC error becomes `RpcError(code, message, data)`; default timeout 30 s; no batching; a malformed frame is only `console.warn`ed.                                                     | Echo the request `id` exactly and answer inside the timeout.                                                                                                                                                                                                                                                                                                                                             |
| `AhpStateMirror` and `HostRuntime` apply **every** envelope, rejected ones included — no `rejectionReason` check exists anywhere in the SDK.                                                                                                       | Feed only accepted echoes to a mirror in tests, or state diverges.                                                                                                                                                                                                                                                                                                                                       |
| `AhpStateMirror` covers root, sessions, terminals, changesets, automations and automation runs — **not chats**; `MultiHostStateMirror` has the same gap.                                                                                           | Check chat parity by calling `chatReducer` directly.                                                                                                                                                                                                                                                                                                                                                     |
| `WebSocketTransport.connect(url)` resolves on `open`; `lastClose` is non-null once closed; an unclean close surfaces as `TransportError("closed")` on the next `recv`.                                                                             | A clean close after `-32005` must not look like an error.                                                                                                                                                                                                                                                                                                                                                |
| `const enum`s (`ActionType`, `SessionStatus`, `SessionLifecycle`, `ReconnectResultType`, `ResponsePartKind`, …) are unreadable as values under Deno's `isolatedModules`.                                                                           | Use literals in tests, pinned once against the runtime object. Real runtime values: `PROTOCOL_VERSION`, `SUPPORTED_PROTOCOL_VERSIONS`, `rootReducer`, `sessionReducer`, `chatReducer`, `AhpErrorCodes`, `JsonRpcErrorCodes`, `IS_CLIENT_DISPATCHABLE`, `MessageKind`, `AhpClient`, `AhpStateMirror`, `InMemoryTransport`, `RpcError`, `WebSocketTransport`, `MultiHostClient`, `immediateForeverPolicy`. |

## 9. Infrastructure requirements

| Need                   | Requirement                                                                                                                                                                                                    |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Listener               | `Deno.serve({ port: 0, hostname: "127.0.0.1" })` over a Hono app, with `upgradeWebSocket` from `hono/deno` on `GET /rpc`.                                                                                      |
| Framing                | One JSON-RPC message per text frame in both directions.                                                                                                                                                        |
| JSON-RPC layer         | A hana collection whose procedure names are the AHP methods; `Hana.handle(frame, { env }, signal)` returns the response frame, or `undefined` for a notification.                                              |
| Per-socket link        | A `link` object binds the socket to a `clientId` on `initialize`/`reconnect`, holds that link's `clientSeq` watermark, and can request "close after this response" for `-32005`.                               |
| Connection replacement | A second `connect` for a live `clientId` drops the old connection together with its subscriptions.                                                                                                             |
| Sequencing             | One global `serverSeq`, persisted, bumped by every commit including rejections.                                                                                                                                |
| Replay ring            | Bounded ring of committed envelopes (default 1024) keyed by `serverSeq`; empty after a restart, which forces snapshots.                                                                                        |
| Storage                | Persistent channel state plus `serverSeq`, keyed so that one template prefix scan lists every instance.                                                                                                        |
| Summary propagation    | Effects: chat mutation → `session/chatUpdated` on the owning session; session summary change → `root/sessionSummaryChanged`; create/dispose → `root/sessionAdded`/`Removed` plus `root/activeSessionsChanged`. |
| Fake agent             | Deterministic, no timers and no randomness: on `chat/turnStarted` emit `chat/responsePart` (markdown), a fixed number of `chat/delta`s, then `chat/usage` and `chat/turnComplete`.                             |
| Request timeouts       | Client requests default to 30 s; wrap every awaited event in a 5 s test timeout so a missing frame fails fast with a message.                                                                                  |
| Sanitizer hygiene      | Deno's op/resource sanitizers are on: call `client.shutdown()`, `multi.shutdown()` and `listener.shutdown()` in every test, guarding the shutdown so a leaked socket fails instead of hanging.                 |

## 10. AHP ↔ Durable Channel mapping

| AHP                                                           | Durable Channel                                                                                                                                                                              |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ahp-root://`                                                 | Route `ahp-root://` — a singleton, segments `["ahp-root:", "", ""]`.                                                                                                                         |
| `ahp-session:/<uuid>`, `ahp-chat:/<cid>`                      | Routes `ahp-session:/:uid` and `ahp-chat:/:cid` — parameterized, so each instance needs an explicit `create`.                                                                                |
| `action.type`                                                 | The action **name**; the payload schema is the remaining fields, with no `type` and no `channel` key.                                                                                        |
| `ActionEnvelope`                                              | `DurableChannelEnvelope` — same `channel`, `serverSeq`, `origin`, `rejectionReason`.                                                                                                         |
| `Snapshot { resource, state, fromSeq }`                       | `DurableChannelSnapshot`, field for field.                                                                                                                                                   |
| `dispatchAction`                                              | `hub.dispatchFrom(clientId, channel, name, payload, clientSeq, { lenient: true })`.                                                                                                          |
| `subscribe` / `unsubscribe`                                   | `hub.subscribe(clientId, uri)` → snapshot / `hub.unsubscribe(clientId, uri)`.                                                                                                                |
| `initialize`                                                  | `hub.connect` plus one `hub.subscribe` per `initialSubscriptions`; `hub.serverSeq` fills the result.                                                                                         |
| `reconnect`                                                   | `hub.reconnect(clientId, lastSeenServerSeq, subscriptions)` → replay \| snapshot, both carrying `missing`.                                                                                   |
| `ping`                                                        | No hub call — answered by the transport layer before any `clientId` binding exists.                                                                                                          |
| `listSessions`                                                | Root-channel command backed by `hub.list("ahp-session:/:uid")`.                                                                                                                              |
| `createSession`/`disposeSession`, `createChat`/`disposeChat`  | Commands on the root and session channels calling `ctx.create` / `ctx.destroy` on the session and chat routes.                                                                               |
| `fetchTurns`                                                  | Chat-channel command that dispatches `chat/turnsLoaded` before returning `{}`.                                                                                                               |
| `root/*` notification                                         | A channel notification whose **name is the wire method**; the wire params are `{ channel, ...payload }`.                                                                                     |
| Summary propagation                                           | `.effect()` on the mutating action.                                                                                                                                                          |
| `SessionNotFound` (`-32001`), `NotFound` (`-32008`)           | `ChannelNotFoundError`, and `RouteNotFoundError` for an unknown URI shape.                                                                                                                   |
| `SessionAlreadyExists` (`-32003`), `AlreadyExists` (`-32010`) | `ChannelAlreadyExistsError`.                                                                                                                                                                 |
| `MethodNotFound` (`-32601`)                                   | `UnknownCommandError`; `UnknownActionError` surfaces inside a rejected envelope instead.                                                                                                     |
| `InvalidParams` (`-32602`)                                    | `InvalidPayloadError`, `InvalidStateError`, `InvalidResultError`.                                                                                                                            |
| no wire equivalent                                            | `NotClientDispatchableError` and `RejectAction` become a rejected envelope, never a JSON-RPC error.                                                                                          |
| Naming convention                                             | An action's name **is** the AHP `type` string and its payload schema has no `type`/`channel` key; a notification's name **is** the wire method and its params are `{ channel, ...payload }`. |

## 11. Decisions and known deviations

| Decision                                                                                                                                                                       | Why                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dispatchAction` is also accepted as a request, answering with the committed envelope.                                                                                         | Lets raw-socket tests assert on the commit; the official client never sends it as a request.                                                                                                                                                                                                                                                        |
| A `clientSeq` at or below the link's watermark is ignored silently — no echo, no sequence consumed.                                                                            | A notification has no response channel on which to report a duplicate.                                                                                                                                                                                                                                                                              |
| Unknown action, server-only action dispatched by a client, or payload failing its schema → a committed rejected envelope with `rejectionReason = "CODE: message"`.             | "Servers MUST echo invalid client actions with `rejectionReason` on the envelope." A missing channel or unknown connection throws instead, since there is nothing to echo on.                                                                                                                                                                       |
| `view.turns` and `delivery.maxLatencyMs` are ignored; the full snapshot is returned.                                                                                           | Both are advisory and clients MUST tolerate more state than requested.                                                                                                                                                                                                                                                                              |
| `session/ready` is dispatched synchronously inside `createSession`.                                                                                                            | Simpler, and no `creating` window is observable — `SessionLifecycle.Creating` is never seen on the wire.                                                                                                                                                                                                                                            |
| The snapshot variant of `reconnect` also carries `missing`.                                                                                                                    | `ReconnectSnapshotResult` has no such field, but the client ignores unknown keys and the replay variant's `missing` is normative.                                                                                                                                                                                                                   |
| `disposeChat`'s `channel` is taken as the chat URI.                                                                                                                            | `DisposeChatParams` carries no `chat` field, so the channel must be the chat. Not stated explicitly — open question.                                                                                                                                                                                                                                |
| `ping` returns `null`, not `{}`.                                                                                                                                               | `CommandMap['ping'].result` is `null`.                                                                                                                                                                                                                                                                                                              |
| `createdAt` and `modifiedAt` live in a private singleton channel `x-catalog://`, never in `SessionState`.                                                                      | A reducer cannot read a clock, and neither timestamp is a `SessionState` field. Effects stamp the catalogue; `listSessions` and the `root/session*` notifications read it back.                                                                                                                                                                     |
| The catalogue channel is a route like any other, but no client is ever told about it.                                                                                          | It needs the same persistence, sequencing and validation as a public channel, so a durable channel is the cheapest index available.                                                                                                                                                                                                                 |
| A protocol-specific refusal is a test-local `AhpError { code }` thrown from a command handler; `guarded()` puts its code on the wire.                                          | The library must not know AHP's error numbers, and `RejectAction` is for reducers. Used for `ProviderNotFound` (-32002) and an unrecognised `listSessions` cursor (-32602).                                                                                                                                                                         |
| `CHANNEL_NOT_FOUND` / `CHANNEL_ALREADY_EXISTS` map to `-32001` / `-32003` when the URI starts with `ahp-session:`, and to `-32008` / `-32010` otherwise.                       | AHP gives sessions their own two codes; everything else falls back to the generic `NotFound` and `AlreadyExists`. `guarded(task, uri)` therefore takes the URI it acted on.                                                                                                                                                                         |
| Session reducers delete a key where `sessionReducer` would set it to `undefined` (`activityChanged`, `defaultChatChanged` with no value).                                      | The two are identical after JSON, and this way the hub's own state stays comparable field for field with a snapshot the client received.                                                                                                                                                                                                            |
| The session state schema keeps only the fields we populate; an unknown key a client sets is dropped, not carried opaque.                                                       | `v.object` strips what it does not declare. Nothing in scope sets `_meta`, `annotations` or `project`; widen the schema when something does.                                                                                                                                                                                                        |
| `createSession` with no `provider` takes the first entry of `RootState.agents`; an unknown provider is `-32002`.                                                               | `CreateSessionParams.provider` is optional and means "the host's default".                                                                                                                                                                                                                                                                          |
| `createSession`'s `config` record is stored as `{ schema: { type: "object", properties: {} }, values: config }`.                                                               | `SessionState.config` is a `SessionConfigState`, schema included; the host declares no config properties yet, so the schema is empty and the values are carried as given.                                                                                                                                                                           |
| `listSessions` sorts by `modifiedAt` descending, then by `resource`, and its cursor is the last `resource` of the page.                                                        | Cursors are opaque and server-defined; a resource is stable, and an unknown one is `-32602` as the spec suggests.                                                                                                                                                                                                                                   |
| A session action naming a chat that does not exist is a no-op, not a rejection.                                                                                                | Faithful to `sessionReducer`. Every action that names a chat (`chatAdded`, `chatUpdated`, `chatRemoved`, `defaultChatChanged`) is server-only, so there is no invalid client action to echo a `rejectionReason` on.                                                                                                                                 |
| **Milestone 4 — chats**                                                                                                                                                        |                                                                                                                                                                                                                                                                                                                                                     |
| The fake agent is `env.agent.reply()` plus `env.tick()`: three fixed chunks for any prompt, one macrotask between two of them.                                                 | Deterministic, no timers of its own and no randomness, yet every dispatch is a commit a test can observe one echo at a time. A scenario that needs a slow agent passes its own `tick` and releases it by hand.                                                                                                                                      |
| The agent runs as `ctx.background` on the chat's URI, launched from the effect of `chat/turnStarted`.                                                                          | A turn outlives the dispatch that started it, and ownership by URI is what makes `disposeChat` (through `destroy`) and `chat/turnCancelled` (through `ctx.abortBackground()`) stop it. `boot().stop()` calls `hub.close()`, so no turn survives a test.                                                                                             |
| A `chat/turnStarted` on a busy chat is a rejected echo whose reason starts with `TURN_IN_PROGRESS`, never AHP's `TurnInProgress` (-32004).                                     | `dispatchAction` is a notification: there is no response frame to carry an error code, and the spec's own rule is that a server echoes an invalid client action with `rejectionReason`.                                                                                                                                                             |
| `view.turns` and `delivery.maxLatencyMs` stay ignored now that turns exist: a subscription always gets every retained turn, and the library has no snapshot projection at all. | Both are advisory and "clients MUST tolerate receiving more state than requested". Trimming `turns` would oblige the host to set `turnsNextCursor` and to page `fetchTurns` for real, which is a different piece of work; a `.view()` the adapter never used would be dead public surface on the isomorphic side, which a client has to mirror too. |
| `fetchTurns` loads nothing and returns `{}`; a cursor it never handed out is `-32602`.                                                                                         | Every retained turn is already in the snapshot, so `turnsNextCursor` is never set and there is no older page to dispatch `chat/turnsLoaded` for.                                                                                                                                                                                                    |
| `x-catalog://` also holds the chat → session link, and is mounted `{ internal: true }`.                                                                                        | `ChatState` does not name its parent, so an effect on a chat has no other way to reach the session it must announce itself to. The internal flag is the library's answer to "a route no peer is ever told about".                                                                                                                                   |
| `createChat` refuses an existing chat URI itself, with `-32010`, before calling `ctx.create`.                                                                                  | One `guarded(task, uri)` maps one URI onto AHP's error table, and `createChat` spans two: a missing session is `-32001` on the session URI, an existing chat is `-32010` on the chat URI.                                                                                                                                                           |
| `-32011 Conflict` for a session that is not `ready` exists but cannot be reached over the wire.                                                                                | `createSession` dispatches `session/ready` before it answers, so any session a client can name is ready. The scenario asserts the refusal through `hub.exec` instead.                                                                                                                                                                               |
| A `SessionSummary`'s `status` is an aggregate of the session's chats; `SessionState.status` keeps only `IsRead` / `IsArchived` and `Idle`.                                     | `sessionReducer` never derives a status from `chats`, so a hub that reduced one into the state would diverge from every client mirroring it. The aggregation therefore lives in `summaryOf` and in the `root/sessionSummaryChanged` notification, which nothing reduces.                                                                            |
| `session/chatUpdated` merges `changes` with its `undefined` values dropped, exactly as JSON dropped them.                                                                      | A merge cannot express "remove this key", so a cleared chat activity lingers in the parent's summary — on the hub and on a client alike, which is what keeps the two comparable.                                                                                                                                                                    |
| Chat reducers delete a key where `chatReducer` would set it to `undefined` (`activeTurn`, `activity`, `draft`).                                                                | Same reason as the session channel: the two are identical after JSON, and the hub's state stays comparable field for field with the snapshot a client holds. `usage` is the exception — the official `Turn` requires the key, so the schema uses `v.undefinedable`.                                                                                 |
| `chat/turnStarted`'s `queuedMessageId` is accepted and ignored.                                                                                                                | Nothing in scope sets `steeringMessage` or `queuedMessages`, so there is no pending message to drop. Both fields are carried opaque.                                                                                                                                                                                                                |
| A chat's `workingDirectories` are not checked against the session's set.                                                                                                       | The check needs two channels' states and a reducer sees one. `createChat` and the two `chat/workingDirectory*` actions therefore take what they are given; enforcing the subset needs a command, which nothing in scope calls.                                                                                                                      |
| `disposeSession` disposes each chat through `ctx.exec(chat, "disposeChat", {})` before destroying itself.                                                                      | Cascading destroy is the definition's business, not the hub's, and going through the child's own command is what keeps `session/chatRemoved` and the catalogue clean-up in one place. The root notifications of a disposal keep the milestone-3 order.                                                                                              |
